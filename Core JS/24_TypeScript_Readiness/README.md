# TypeScript Readiness

## What is it?
TypeScript Readiness covers why TypeScript matters and the core static typing concepts that frontend developers should understand.

## Why it matters
Even in JavaScript-focused roles, recruiters and senior engineers expect candidates to understand TypeScript concepts because they improve code correctness and maintainability.

## Topics covered
- structural typing
- type inference
- generics
- utility types
- enums vs interfaces vs types

## Interview questions and answers

### Why use TypeScript?
TypeScript adds static typing to JavaScript, catches errors earlier, improves editor tooling, and documents contracts in code.

### What is structural typing?
Structural typing means compatibility is determined by the shape of data rather than explicit inheritance. Two objects are compatible if they have required members with matching types.

### How does type inference work?
TypeScript infers types from initial values, function return values, and assignments. This reduces the need for manual annotations while preserving safety.

### When do you use generics?
Use generics when you want to write reusable functions or types that work with multiple data types without losing type information.

### What is the difference between interfaces and type aliases?
Interfaces are primarily for describing object shapes and can be extended or merged. Type aliases can describe any type, including unions and tuples.

## Quick revision
- TypeScript is a superset of JavaScript.
- structural typing compares compatibility by shape.
- generics let you write reusable, type-safe abstractions.
- interfaces are best for object contracts.
- utility types help transform existing types.
